# Athena Build Log — Nov 17, 2026

## Summary
Today was about making Athena reliable and backed up. My private notes now back themselves up to GitHub every night, the morning briefing has a startup routine so it can actually run at 7:30 AM, and this public build log went live.

## What got done

### 1. Private vault backup to GitHub
- My Obsidian vault was already a Git repo, but nothing had ever reached GitHub. The cause was a one-letter typo in the upload address.
- Fixed the address, switched Git to GitHub's private "noreply" email so my real email stays out of the history, and rewrote the one old commit that still had it.
- Ran a safety scan before the first upload: no passwords, keys or tokens in the vault. Added a `.gitignore` for secret file types and Obsidian's constantly-changing layout files.
- First upload done: the private repo matches my PC exactly.

### 2. Automatic nightly backups
- A small script commits and uploads any vault changes every night at 11 PM, through Windows Task Scheduler with no window.
- If nothing changed, it does nothing. If an upload fails, it catches up the next night. It never deletes or rewrites anything.
- Every run adds one line to a log file, so checking it takes 5 seconds.

### 3. Fixing the morning briefing
This morning's 7:30 AM briefing never arrived. There were three separate causes:
1. **The PC was asleep.**
2. **The Hermes gateway had crashed the day before**, and its "start at sign-in" task doesn't run when the PC just wakes from sleep.
3. **The local model skipped saving the note.** It wrote and sent the plan but never saved the file (2 of 7 runs so far).

Fixes:
- A new **"Athena Morning Start"** task wakes the PC at 7:15 AM on weekdays. It keeps the PC awake, restarts the Hermes gateway if it's down, turns on LM Studio's server and loads the Qwen model. It also runs right after I sign in.
- Made the morning job's save step explicit, with the exact file path and the tool to use.
- Tested it: from a cold LM Studio, the model was loaded in 13 seconds, and the job saved the note and sent it to Discord.

### 4. This public build log
- Created this repo, separate from my private vault.
- Built a **publish script** with a Desktop shortcut. It scans new files for anything private (personal info, emails, IDs, tokens), shows what will be published, and asks y/n before uploading.
- The script itself is kept out of the repo, because it has to contain the private words it searches for.

## Lessons learned
- **One typo can silently break everything.** The backup "worked" for days but never reached GitHub.
- **"Start at sign-in" is not "start every morning."** Waking from sleep doesn't count as signing in.
- **Privacy tools can leak too.** A checker that searches for your name has to contain your name.
- **Keep private and public apart by design.** The vault and the public log live in separate folders and separate repos, so one can't leak into the other.
